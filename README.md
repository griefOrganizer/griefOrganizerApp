<h1><strong>Next Step</strong></h1>
Next Step is a mobile app that aims to help people handle administrative tasks that come with losing a loved one (or preparing to lose a loved one). The goal is to take it one step at a time. This is a senior capstone project.

<strong>Tech Stack</strong>
Frontend: React Native with Expo (Typescript)
Backend: Supabase (Auth, autogenerated REST API, Edge Functions in TypeScript)
Database: PostgreSQL (in Supabase)
Navigation: Expo Router (every file in app/ is a screen)
  (tabs) and [id] indicate groups of tasks or groups of pages

<strong>How to get started</strong>
Before beginning, you need Node.js, Git, Expo Go app on a mobile phone, and access to Next Step's Supabase project and GitHub organization.
Then,

<code> git clone https://github.com/YOUR-ORG/griefOrganizerApp.git
cd griefOrganizerApp
npm install
cp .env.example .env
npx expo start </code>

Fill in the .env file as explained below and as shown in .env.example then scan the QR code that will take you to Expo Go.

Do not use a umich.edu email as the organization has blocked Google OAuth so although you can create an account with that email, connecting the email to find data will fail.

<strong>Environment Variables</strong>
.env file needs to have the Supabase project's publishable key as well as its URL. .env.example provides a .env template for reference when setting up the project locally.

<code>EXPO_PUBLIC_SUPABASE_URL=
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
EXPO_PUBLIC_GEOAPIFY_KEY=</code>

Friendly reminder to not commit a .env file.

<strong>Icons</strong>
This project uses Lucide icons for simplicity and consistency. View options for icons and find their associated names here: https://lucide.dev/icons/ To use an icon, import the icon with its name from 'lucide-react-native' and implement using <Icon icon={IconName} />
For example:
<code>import { Clock } from 'lucide-react-native'
import { Icon } from '../components/Icon'

<Icon icon={Clock} size={18} /></code>

<strong>Address autofill</strong>
To enable address autofill in the user details page:
- sign up at geoapify.com
- set project's API key to EXPO_PUBLIC_GEOAPIFY_KEY in .env

<strong>Supabase</strong>
Tables: profiles, tasks_templates, user_tasks, connections, email_connections, oauth_states
Tables all have Row Level security turned on to restrict users to only being able to view and change their own data. This is to prevent accidental changes that affect unrelated users. Deleting a user in the Users table (not a SQL created table) in Authentication also deletes all their related data due to all tables using <code>on delete cascade</code>.
New users receive starter tasks automatically upon selecting that they "lost a loved one" or are "preparing for loss" from a database trigger that copies the matching rows from task_templates into user_tasks.

(only need to do this once) link you local project to Supabase:
<code>npx supabase login
npx supabase link --project-ref YOUR-PROJECT-REF</code>

<strong>Edge Functions</strong>
There are three edge functions run by the gmail connection. The goal is for google's tokens to never come in contact with user's phones. Deploy these edge functions with the following:
<code>npx supabase functions deploy gmail-auth-url
npx supabase functions deploy gmail-callback
npx supabase functions deploy gmail-disconnect</code>

*note:* do not remove verify_jwt=false for gmail-callback in supabase/config.toml because Google calls it directly.

<strong>Gmail REST API details:</strong>
- This is a capstone project and is not being published with a real launch so we can have up to 100 users added as "test users" in the Cloud Console
- Users will be warned that "Google hasn't verified this app" and have to click continue
- Users must reconnect weekly because refresh tokens expire after 7 days (as opposed to tokens that only expire when they are revoked if this app were truly published)
- Pro: Google's app verification for a published app costs money and requires an annual third-party security assessment which we are not completing for this capstone project
- Once again, this will not work if a user is using a umich.edu affiliated email

To test it, your Google account has to be added under Google Auth Platform → Audience → Test users in the Next Step Cloud Console project. The Gmail callback URL (https://YOUR-PROJECT-REF.supabase.co/functions/v1/gmail-callback) has to be listed under the client's Authorized redirect URIs or Google will show redirect_uri_mismatch.

<strong>Troubleshooting</strong>
*If the app skips sign in then can't save anything:* your phone remembered a login for an account that was deleted. Reload the app and it should send you to sign in after that.
*If something has gone wrong connecting email and you receive 400 from gmail-auth-url:* make sure you're not testing with somewhere other than Expo Go. For example, make sure you're not using a development built (exp+grieforganizer://…), you're not in tunnel mode (exps://…), or you're not using the web preview (http://localhost…).
